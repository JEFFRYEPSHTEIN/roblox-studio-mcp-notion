# Ручная оценка работы агента

**Статус: оценка не выполнена.** Roblox Studio для этих вопросов не запускался, тестовый Place не создавался. Ожидаемые ответы в `evaluation.xml` выведены из исходника `../examples/evaluation-fixture.luau`; они ещё не подтверждены ответами реальных инструментов Studio. Успешные протокольные тесты проекта не заменяют эту оценку.

## Что проверяется

Десять независимых вопросов требуют сопоставить дерево объектов, атрибуты, свойства и исходники нескольких конфигураций. Проверяются навигация по выбранному Place, сохранение `studio_id`, выбор подходящих инструментов и получение точного ответа. Вопросы не требуют выполнения кода, изменения скриптов, запуска Play или публикации игры.

Разрешённые инструменты для оценки: `roblox_list_roblox_studios`, `roblox_get_studio_state`, `roblox_search_game_tree`, `roblox_inspect_instance`, `roblox_script_search`, `roblox_script_grep`, `roblox_script_read`. Изображения можно читать, но они не нужны для ожидаемых ответов. `execute_luau`, `multi_edit` и `start_stop_play` использовать нельзя.

## Подготовка данных пользователем

1. Создайте **новый одноразовый Place** в Roblox Studio. Не устанавливайте пример в существующую игру. Оставьте Studio в режиме редактирования, без Play.
2. Просмотрите `../examples/evaluation-fixture.luau`. Включите Command Bar через меню View и вручную выполните в ней содержимое файла один раз. Это отдельная операция подготовки, которая создаёт тестовые объекты; сама оценка затем использует только чтение.
3. Убедитесь, что папки `McpEvaluationV1` появились в Workspace, ReplicatedStorage, ServerScriptService и StarterGui. Если выполнение завершилось ошибкой, используйте новый одноразовый Place. Повторная установка в папки с тем же именем намеренно отклоняется; существующие объекты не удаляются и не заменяются.
4. Все создаваемые Script/LocalScript отключены. ModuleScript служат источниками данных; не вызывайте `require`, не запускайте Play и не меняйте fixture между вопросами.
5. Включите встроенный Studio MCP по основной инструкции проекта. Остановите мост через `stop.ps1`, установите `readOnly: true` в локальном `.runtime/config.json`, сохраните остальные поля и запустите мост снова. При изменении HTTPS-адреса обновите подключение Notion. Ключи из этой папки в GitHub не помещайте.
6. Через `roblox_list_roblox_studios` получите список открытых экземпляров. **Пользователь должен явно указать идентификатор тестового Place.** Не выбирайте другой открытый проект автоматически. Динамический идентификатор не записывается в опубликованный XML.

Fixture создаёт nested-объекты и теги `McpEvalV1`/`McpEvalGate`/другие. Для поиска доступны обычные пути; теги не требуют отдельного инструмента. Объекты имеют статические смысловые атрибуты, поэтому вопросы не зависят от Roblox UniqueId, аккаунта или даты запуска. Скрипт не использует сеть, загрузку ресурсов и внешние модули.

## Проведение оценки через Notion

Для каждого `<qa_pair>` откройте отдельный чат, разрешите подключение Roblox MCP и передайте только текст `<question>` вместе с выбранным пользователем `studio_id`. Эталон из `<answer>` агенту не передавайте. Пример общего контекста перед вопросом:

> Используй подключение Roblox Studio MCP. Тестовый Place выбран мной; studio_id: укажи полученный идентификатор. Оставайся в Edit и используй только инструменты чтения. Если этот идентификатор недоступен или fixture отсутствует, сообщи ошибку и остановись. Не выбирай другой Place.

`roblox_get_studio_state` позволяет убедиться, что Edit доступен. При поиске дерева передавайте `datamodel_type: "Edit"`, начинайте с конкретного корня fixture и используйте `head_limit: 8`. Глубоко вложенные объекты исследуйте последующими запросами с найденным `path`, чтобы ограничение результатов не скрывало нужные элементы. Инструмент читает скрипты по пути вида `game.ReplicatedStorage.McpEvaluationV1.Configurations.EntryPolicies`.

Зафиксируйте окончательный ответ, использованные инструменты и наличие всех нужных частей доказательства. Сравнивайте ответ с XML как точную строку, без пояснений и оформления. Каждую пару можно выполнять отдельно в любом порядке; результаты предыдущих вопросов не требуются.

## Как зафиксировать результат

Сохраните локальный отчёт, например `.runtime/evaluation-report.md`, со строками: номер вопроса, ожидаемый ответ, фактический ответ, совпадение, число обращений к инструментам и замечания. Этот каталог исключён из Git. Различайте ошибку подключения, отсутствие fixture, пропущенные данные и неверное рассуждение агента.

После первого реального выполнения отдельно прочитайте данные Studio инструментами чтения и проверьте каждый эталон. Если источник не установился корректно или официальный MCP не возвращает необходимое свойство, пометьте вопрос как непроверенный; не объявляйте успешную оценку по одному исходнику fixture. Повторные оценки требуют того же неизменённого fixture v1.

Автоматический оценочный runner и ключи провайдеров моделей не входят в эту папку. XML совместим с форматом `<evaluation><qa_pair><question>…</question><answer>…</answer></qa_pair></evaluation>`; внешний runner должен поддерживать Streamable HTTP, Bearer, контекст явно выбранного Studio и ограничение инструментов чтением.

Использованные API fixture: [Script.Source](https://create.roblox.com/docs/reference/engine/classes/Script) и [CollectionService](https://create.roblox.com/docs/reference/engine/classes/CollectionService). Исходные данные примера вымышлены.
